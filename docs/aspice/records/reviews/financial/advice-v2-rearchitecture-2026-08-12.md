# Advice V2 重构评审记录（2026-08-12）

## 评审结论

V1 的输出无法稳定回答“当前应关注哪个方向、在哪个区域等待、看到什么才确认、什么条件使建议失效”。继续保留多 Agent 辩论、Trader/Risk/Manager 授权和多方案报告会扩大解释链，却不能提高人工决策价值。因此本基线直接删除 V1 实现，Git 历史作为追溯与恢复手段。

## 产品目标

当前系统只提出合理、可证伪的交易建议，由用户人工确认是否执行。自动下单、仓位执行、券商接入和执行授权均为后续范围。

## 退役范围

- Analyst / Bull / Bear / Debate / Trader / Risk / Manager 决策链及其数据类型和页面。
- V1 `signals`、`agent_trace`、`projections`、`validated_plans` 报告契约。
- LLM 多阶段决策、点位提案和报告叙事覆盖。
- 与 V1 信号模型绑定的回测、风险门禁、信号 identity 和旧审计链。
- 对应脚本、测试、ASPICE 需求、组件和说明文档。

历史运行文件不删除，但回放只从保存的行情与结构数据重建 Advice V2；旧建议文本不作为当前建议显示。

## 保留范围

- 多周期行情、外部数据采集和显式降级。
- 指标、PA/ICT/SMC 结构和支撑阻力事实。
- RunConfig、进度、归档、回放和 Streamlit 生命周期基础设施。
- OpenAI-compatible 客户端、重试、预算与遥测基础设施，仅供一次文案增强使用。

## 新架构验收条件

1. 决策只能是 `WAIT`、`WATCH_LONG`、`WATCH_SHORT`、`AVOID`。
2. 一次最多一个首选方案；无足够证据时必须明确无方案。
3. 首选方案含关注区、人工确认清单、失效位、最多两个目标、证据 ID 和风险收益比。
4. 方向和数字由确定性代码产生并审计；LLM 只能编辑文字。
5. 报告为 `human_review_advice` v2，且不再包含 V1 顶层键。
6. 界面不提供自动执行控制，并明确要求人工确认。
7. 需求、架构、详细设计、测试和验证证据按 Advice V2 重新双向追溯。

## 实跑验证

使用历史归档 `20260811T143236Z` 重建时，Advice V2 形成 `WATCH_LONG`：当前价 4386.97，关注区 4367.68–4376.64，失效位 4359.53，目标 4397.42 / 4420.50，证据 3 条，目标风险收益约 2.00R / 3.83R，确定性审计通过。该结果仅说明建议契约能够在真实历史快照上工作，不构成交易执行结论。

## 追溯处置

旧实现、测试和文档通过 Git 保留。ASPICE 当前基线只追溯 Advice V2；V1 发现项不伪装为当前已验证需求，而以本评审记录的“退役范围”统一关闭。
